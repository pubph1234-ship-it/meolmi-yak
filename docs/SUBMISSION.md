# GitHub 저장소와 1차 제출

공식 안내 재확인: 2026-11-11. 접수 기간은 2026-10-21~11-15입니다. 최종 접수 전 변경 공지를 다시 확인하세요.

기획서 겸 접수양식이 필수이며 시연 영상, GitHub 저장소 및 APK는 선택 제출/가산점 대상입니다. 가산점의 정확한 점수나 수상은 보장할 수 없습니다.

## 계정/저장소가 아직 없다면

1. 팀 대표의 GitHub 계정을 준비합니다. 비밀번호를 이 채팅이나 코드에 적지 않습니다.
2. GitHub에서 새 저장소를 만듭니다. 추천 이름은 `meolmi-yak`입니다. 공개 일정 누락을 피하려면 처음부터 Public으로 만드는 방법을 권장합니다.
3. 함께 제공하는 **GitHub 업로드용 소스 ZIP**을 풀어 그 안의 파일을 업로드합니다. `app/`, `gradle/`, Gradle 빌드 파일, README, `docs/`, `apk/`가 포함되어야 합니다.
4. 개발 작업 폴더를 브라우저에 통째로 올리지 마세요. 브라우저 업로드는 `.gitignore`를 자동 적용하지 않습니다. 배포 ZIP에는 `local.properties`, `signing.properties`, 키스토어, `.gradle/`, `app/build/`를 제외해 두었습니다. Git CLI로 올릴 때는 `.gitignore`가 적용됩니다.
5. APK가 브라우저 업로드 제한을 넘으면 Git CLI를 사용합니다. GitHub 일반 파일 한도를 넘으면 공식 안내에 따라 Releases에 올리고 링크를 제출합니다.
6. 비공개 저장소도 접수할 수 있으며 심사용 계정을 Collaborator로 초대할 필요는 없습니다. 다만 2026년 11월 16일까지 Public으로 전환하고 1차 심사 결과 발표일인 11월 23일까지 공개 상태를 유지해야 합니다. 공개로 전환하지 않으면 개발 산출물 가산점이 반영되지 않습니다.
7. 접수 메일에는 저장소 주소와 **최종 커밋 번호(commit hash)**를 기재합니다. 심사는 해당 커밋 기준으로 진행됩니다. 업로드 완료 후의 커밋 번호를 사용하세요.
8. 공개하기 어려운 경우 소스와 APK를 압축한 파일의 다운로드 주소를 접수 마감 전까지 메일로 제출하는 대안이 있습니다. PC 로컬 경로는 외부 다운로드 주소가 아닙니다.

로컬 소스는 준비해 두지만, 계정/저장소가 정해지기 전에는 원격 업로드가 완료된 상태가 아닙니다.

## 접수 직전

- APK를 새 설치 후 직접 실행하고, 영상과 제출 APK의 기능이 일치하는지 확인합니다.
- 영상에 **시연 · 가상 데이터**가 드러나도록 촬영합니다. SDK 실시간 연동과 앱 내부 가상 시연을 혼동시키지 않습니다.
- README 검증 범위와 제한을 유지합니다. 미검증 실차 동작/멀미 감소 수치를 추가하지 않습니다.
- 저장소 주소, APK 경로, 영상 링크를 접수양식에 입력하고 접수 메일에 최종 커밋 번호를 적습니다.
- 대표자와 참가자 전원의 개인정보 동의·서명을 준비합니다. 이메일 제목/수신/CC 규칙은 공식 페이지를 따릅니다.
- 2차 PT 대상이 되면 PT 전까지 실제 동작하는 앱을 완료해야 하며, 제출 후 고도화가 가능합니다.
