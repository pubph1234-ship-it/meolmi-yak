# 코칭 로직과 데이터의 의미

`CoachEngine`은 Android와 분리한 순수 Kotlin 로직입니다. 인공지능 모델이나 임상적으로 검증된 멀미 척도가 아닙니다.

- 속도 유효 범위: 0~100 m/s, 조향각 절댓값 1080도 이하. NaN/무한대/범위 밖은 누락 처리.
- 역전·중복 시각은 거부. 0.15~2초 구간의 속도 차이를 시간으로 나누어 종가속도를 추정.
- 추정 가속도는 EMA(이전 0.55, 새 값 0.45)로 평활화. 절댓값 12 m/s² 초과 변화는 이상치로 버림.
- 가속/감속 추정 기준 ±2.2 m/s². 같은 종류 이벤트는 5초 간격. **설계용 임시 기준이며 멀미·운전 능력 기준이 아님.**
- 조향각 변화율 55도/초 초과 및 속도 3 m/s 초과일 때 조향 변화 기록. 차체의 횡가속도로 바꾸지 않음.
- 경로 정보는 2.5초 이내, 속도 샘플은 1.5초 이내여야 안내 가능. 현재 속도 2 m/s 이상에서 거리/속도로 추정한 도달 시간이 3~12초면 짧게 안내.
- 동일 경로 이벤트는 한 번 안내. 전체 안내 사이 최소 간격 15초, 적게 안내 설정은 25초.
- 체감 입력은 3초 간격으로 중복 방지. OK/불편/휴식 요청의 주관적 기록을 그대로 보존.
- 가장 많이 감지한 변화 종류를 바탕으로 목표 하나 제안. 데이터가 부족하면 판단 보류 문구를 제공.
- 최근 10회 로컬 보존. 1회 최대 1시간, 샘플 7200개/이벤트 600개로 제한.

뒷좌석 가속도, 개인별 민감도, 노면, 급제동의 필요성, 교통 상황, 멀미의 실제 발생 여부를 이 데이터만으로 알 수 없습니다. 실제 도로 적용 전 차량 신호의 단위·갱신율·오차·지연 검증과 사용자 평가가 필요합니다.

## 0.2 체감 연계 코칭

UNEASY 입력 직전 최대 20초(출발 전으로 넘어가지 않음)를 살펴봅니다. OK와 REST는 불편 원인 분석의 기준점으로 쓰지 않습니다. REST는 휴식 요청으로 전달합니다. 20초는 시제품 설계값이지 임상 기준이 아닙니다.

윈도 안의 ACCELERATION/BRAKING/STEERING만 목표 선택에 사용하고 CUE는 참고 정보로 표시합니다. 겹친 윈도의 원본 이벤트는 한 번만 집계합니다. 가장 많은 종류에 따른 목표를 고르고, 동점이면 복합 목표를 제시합니다. 불편 입력이 있어도 대응 이벤트가 없으면 ‘확인되지 않음’으로 표시합니다. 불편 입력이 없으면 기존 전체 주행 요약으로 돌아갑니다.

신호 누락, 입력 지연, 필요한 회피/제동 때문에 기록이 체감을 충분히 설명하지 못할 수 있습니다. 이벤트 횟수가 적다는 사실로 멀미 감소를 추론하지 않습니다. 과거 0.1 기록은 저장 당시 목표를 유지합니다.
